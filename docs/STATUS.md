## Відомі баги й обмеження

- Не перевірено на реальній версії WPML і реальній темі сайту. Невідомо, які функції WPML тема використовує
  поза реалізованими в `compat-wpml.php`.
- Режим WPML «показувати оригінал, якщо перекладу немає» (`custom_posts_sync_option = 2`) обробляється як
  звичайний «перекладається»: запис без перекладу іншою мовою не показується.
- Налаштування WPML Flag in Menu Extended не імпортуються (назва його опції невідома), тож вигляд
  перемикача треба вибрати вручну. CSS може не збігатися зі старим виглядом.
- Gettext-рядки шукаються лише за контекстом = text domain. Старий формат контексту WPML
  `theme <назва>` не підтримується.
- Немає інтерфейсу редагування рядків (String Translation), черг і автоматичного перекладу.
- Медіафайли спільні для всіх мов. WooCommerce Multilingual і переклад slug типів записів не реалізовані.
- Колонка «Мови» у списку рубрик створює рядок у `icl_translations` для рубрик без мови прямо під час
  рендерингу (побічний ефект у відображенні; нешкідливо, але негарно).
- Кожен пункт перемикача в меню викликає `get_post(-1000…)` у фільтрі `the_title`: зайвий запит до БД на пункт.
- `do_action('wpml_switch_language')` не скидає кеш посилань перемикача.
- У форматі «домен» не вирішено cookies/вхід між доменами.
- Продуктивність фільтрів (`EXISTS` на кожен перекладний тип) на великій базі не вимірювалась.
- PHPCS (WordPress Coding Standards) не запускався: у середовищі його немає.
- Відмова в доступі для `create_translation` (немає прав / не той тип) перевірена рев'ю коду, але
  не e2e-тестом.

## Наступні кроки (за пріоритетом)

1. **Перевірка на копії реального сайту:** бекап БД → staging → деактивувати WPML → активувати плагін →
   пройти головні сторінки обома мовами, меню, перемикач, форми, пошук. Записати знайдене сюди.
2. **Аудит теми:** `grep -rnE "icl_|wpml_|ICL_|\$sitepress" wp-content/themes/<тема>`. Дописати в
   `compat-wpml.php` усе, чого бракує, і покрити це e2e-перевіркою.
3. **Підлаштувати вигляд перемикача** під поточний WPML Flag in Menu Extended (CSS, порядок, назви).
4. Реалізувати режим «показувати оригінал, якщо перекладу немає» для типів із `sync_option = 2`, якщо він
   використовується на сайті.
5. Підтримати контекст рядків `theme <назва>` і за потреби зробити простий інтерфейс редагування рядків.
6. Запустити PHPCS з WordPress Coding Standards і виправити зауваження.
7. Додати e2e-перевірки відмов доступу (`create_translation` без прав, підроблений trid через форму).
8. Прибрати побічний запис у БД під час рендерингу колонки рубрик і зайвий `get_post()` для пунктів меню.
9. Виміряти продуктивність на копії реальної бази, за потреби додати кешування.
10. Злити в `main` через PR, підготувати zip для встановлення (`agroeco-multilingual.zip`).
